## What is it

**Imposterio** (a portmanteau of *imposto* — the Portuguese word for "tax" — and *mistério*, meaning "mystery") is a public transparency platform that aggregates, in real time, data from dozens of official Brazilian government APIs to answer one simple question:

> *What are you, taxpayer, actually funding with your money?*

Every number displayed comes directly from an official government source — with a link button pointing to the exact API call that generated that data. No middlemen, no interpretation: just the raw data, plain and clear.

## ✨ Features

### 📊 General dashboard
A consolidated view of all branches of government with configurable period rankings (7 days, 30 days, 6 months, 1 year):
- Parliamentarian with highest and lowest spending (CEAP — parliamentary quota)
- Parliamentarian with best and worst attendance
- Parliamentarian with most and fewest aides
- Total cost per branch, per party, per state

### 🏛️ Chamber of Deputies (Câmara)
Per deputy: salary, detailed expenses by category, attendance at each session, votes (including party-line alignment), bills introduced and approved, aides and their salaries, earmarks sent to municipalities, parliamentary caucuses, and floor speeches.

### 🏛️ Federal Senate (Senado)
Per senator: the same data as the Chamber, plus reports issued, opinions authored, and complete history of previous terms.

### ⚖️ Judiciary
Per court and per judge: compensation (including allowances that exceed the constitutional salary ceiling), productivity (cases ruled per month), average case duration, cost per ruling. Data sourced from CNJ/DataJud and individual court transparency portals.

### 🏢 Executive Branch
Per ministry and per public official: detailed compensation of ministers, career civil servants, and political appointees; travel and per-diem spending; contracts awarded; bids conducted; agreements with states and municipalities; mandatory earmarks.

### 🕸️ Companies and interest networks
Per CNPJ (corporate tax ID): total received from the federal government, total received via CEAP from parliamentarians, campaign donations made, political ROI (donated vs. received), network of partners and all companies linked to each CPF (individual tax ID), bid participation history (wins and losses), CEIS/CNEP blacklist alerts.

### 🎮 Fair or not? (*Acha Justo?*)
A transparency game: the platform displays a real expense by a public official without revealing who it is. You vote whether you think it's fair or not. Afterward, the reveal shows the name, photo, party, and all available information about that official. The votes form popular disapproval rankings by official, party, spending type, and state — original data generated by Imposterio itself.

## 🔗 Data sources

All data is consumed in real time from official sources. No government data is stored in a proprietary database — only in a temporary Redis cache to avoid overloading public APIs.

| Source | Data | Swagger / Docs |
|---|---|---|
| Chamber of Deputies | Deputies, expenses, votes, attendance, bills | [dadosabertos.camara.leg.br](https://dadosabertos.camara.leg.br/swagger/api.html) |
| Federal Senate | Senators, bills, votes, speeches | [legis.senado.leg.br](https://legis.senado.leg.br/dadosabertos/api-docs/swagger-ui/index.html) |
| Transparency Portal | Federal executive, civil servants, contracts, blacklists | [api.portaldatransparencia.gov.br](https://api.portaldatransparencia.gov.br/swagger-ui/index.html) |
| CNJ / DataJud | Judges, cases, judicial productivity | [datajud-wiki.cnj.jus.br](https://datajud-wiki.cnj.jus.br/api-publica/) |
| TSE (Electoral Court) | Candidates, declared assets, campaign donations | [dadosabertos.tse.jus.br](https://dadosabertos.tse.jus.br/) |
| Federal Revenue (QSA) | Partners and corporate networks (full monthly bulk) | [dados.gov.br](https://dados.gov.br/dados/conjuntos-dados/cadastro-nacional-da-pessoa-juridica---cnpj) |
| CNPJá | Individual real-time CNPJ lookup | [open.cnpja.com](https://open.cnpja.com) |

## 🏗️ Architecture

Imposterio is built on the principle of **minimal proprietary storage**: data flows from official APIs, passes through a Redis cache with TTL configured per data type, and reaches the user with the exact URL of the call that generated it.

```
Official APIs → Next.js (fetching + normalization) → Redis (TTL cache) → Frontend
                                                    ↓
                                               PostgreSQL
                                          (game votes only +
                                           Federal Revenue QSA bulk)
```

**Stack:**
- **Frontend + API:** Next.js 14 with App Router and TypeScript
- **Cache:** Redis via Upstash (serverless, no fixed cost)
- **Database:** PostgreSQL via Neon (exclusively for game votes and the Federal Revenue QSA bulk import)
- **Deploy:** Vercel (web) + Railway (monthly QSA import worker)

**Monorepo with Turborepo:**
```
imposterio/
├── apps/
│   ├── web/          # Next.js — frontend + API Routes
│   └── worker/       # Monthly Federal Revenue QSA import
├── packages/
│   ├── db/           # Prisma schema + queries
│   ├── fetchers/     # Clients for each public API (with _source injected)
│   └── types/        # Shared TypeScript types
├── CLAUDE.md         # Claude Code instructions
└── README.md
```

**The `_source` principle:** every piece of data returned to the frontend carries a `_source` field with the exact API URL that generated it. The `<SourcePill>` component renders this link next to every data point, allowing any user to verify the information directly at the official source.

## 🚀 Running locally

### Prerequisites
- Node.js 20+
- pnpm 9+
- Free account at [Upstash](https://upstash.com) (Redis)
- Free account at [Neon](https://neon.tech) (PostgreSQL)
- Free API key from [Portal da Transparência](https://portaldatransparencia.gov.br/api-de-dados/cadastrar-email)

### Setup

```bash
# 1. Clone the repository
git clone https://github.com/your-username/imposterio.git
cd imposterio

# 2. Install dependencies
pnpm install

# 3. Configure environment variables
#    The example file lives at the repo root. Copy it to apps/web/.env.local
#    (the path Next.js reads) and fill in your keys.
cp .env.example apps/web/.env.local

# 4. Generate the Prisma Client
#    Required before the first `pnpm dev`, and again whenever
#    packages/db/schema.prisma changes.
pnpm --filter @imposterio/db db:generate

# 5. Apply the database schema (pick one)
#    - Development (creates/updates migrations):
pnpm --filter @imposterio/db db:migrate
#    - Or just sync the schema without creating a migration:
# pnpm --filter @imposterio/db db:push

# 6. Start the dev server (web + worker via Turborepo)
pnpm dev
```

The web app starts on `http://localhost:3000` (or the next free port, e.g. 3001).

### Environment variables

Minimum set to boot the app — see [`.env.example`](./.env.example) for the full list, with comments and links for each provider.

```env
# PostgreSQL (Neon) — game votes + QSA bulk
DATABASE_URL=

# Redis (Upstash) — cache for all public APIs
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=

# Portal da Transparência — free key (email registration)
TRANSPARENCIA_API_KEY=

# (Optional) DataJud/CNJ public key — available in the official wiki
DATAJUD_API_KEY=
```

### Useful scripts

```bash
pnpm dev                                  # web + worker in dev mode
pnpm build                                # build all apps
pnpm test                                 # run tests (Vitest)
pnpm test:coverage                        # tests with coverage
pnpm lint                                 # lint across the monorepo
pnpm --filter @imposterio/db db:studio    # open Prisma Studio
```
